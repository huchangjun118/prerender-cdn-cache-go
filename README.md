# prerender-cdn-cache-go

面向动态页面的预渲染与边缘缓存服务。页面可按构建期预生成（SSG）、请求时实时渲染（SSR）
或按内容变更增量再生（ISR），内容发布后缓存按正确粒度与版本对外更新。

## 运行

```bash
go run ./cmd/server   # 监听 :8080
```

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `PUT` | `/routes/{route}` | 声明路由配置（渲染模式、TTL、标签、失败策略） |
| `POST` | `/publish/{route}` | 渲染并**原子发布**一个新版本；SSG 路由同时回填缓存 |
| `POST` | `/invalidate` | 提交失效事件 `{seq, tag, version}`，按标签定向失效 |
| `GET` | `/pages/{route}` | 读取页面，行为由路由声明的模式决定 |

路由声明示例：

```json
{
  "mode": "isr",                // ssg | ssr | isr
  "freshTTLMs": 60000,          // 新鲜期：期间缓存直接命中；<=0 视为长期有效
  "staleTTLMs": 300000,         // 陈旧窗口：新鲜期结束后仍可用于失败兜底
  "stalePolicy": "serve-stale", // serve-stale | fail
  "tags": ["landing", "site"]
}
```

### 可观测性

每次读取的缓存行为都可从响应头/状态码观察：

| 响应头 | 取值 |
| --- | --- |
| `X-Cache` | `HIT`（新鲜命中）/ `MISS`（实时渲染或回填）/ `STALE`（失败兜底返回陈旧内容）/ `ERROR` |
| `X-Content-Version` | 实际返回内容的版本号 |
| `X-Render-Mode` | 产出该内容的渲染模式 |

`STALE` 返回 200；再生失败且策略为 `fail`（或已超出陈旧窗口）返回 503 且 `X-Cache: ERROR`；
路由从未发布或已提交版本被失效覆盖时返回 404。

## 渲染模式

三种模式可共存，每条路由单独声明。**缓存条目记录产出它的模式，读取时校验与路由声明一致，
绝不串用其它模式产出的页面**（路由改声明后，旧模式条目不会被命中）。

- **SSG**：运行时不回源。发布时渲染并提交版本、回填缓存；读取只命中缓存或从已提交版本回填。
  已提交版本被失效覆盖后，在新发布之前返回 404。
- **SSR**：每次请求回源实时渲染，不写缓存。回源失败时按 `stalePolicy` 回退到最近已提交版本
  （`STALE`）或直接报错。
- **ISR**：新鲜期内命中缓存；过期或缺失则回源再生并回写。再生失败且处于陈旧窗口内时，
  按 `stalePolicy` 返回陈旧内容（`STALE`）或报错。

## 缓存一致性语义

### 原子发布

`ContentStore.Commit` 只在完整 `Page` 构造完成后一次性替换已提交指针；`Page` 提交后不可变。
读取方任何时刻只能看到某个已提交的**完整版本**，不会看到半成品或字段级混合。
版本号单调递增，迟到的旧版本提交会被拒绝，不会回滚已发布内容。

### 定向失效与版本水位

失效事件 `{seq, tag, version}` 的语义是：**该标签下版本 ≤ version 的内容全部失效**。

- 按标签定向：只有携带该标签且版本被覆盖的条目退出缓存，其余页面继续命中，不触发整站清空。
- 每个标签维护**只升不降的版本水位**。失效与到达顺序无关，因此乱序、重复、迟到的事件
  最终都收敛到与按序全量处理一致的状态（按 `seq` 幂等去重，按版本水位合并）。
- 迟到事件不会复活已清除的页面：`Fill` 会拒绝版本不高于标签水位的写入；
  并发下"失效先至、旧写后到"的竞态因此安全。
- 失效不会丢失刚提交的新版本：新版本号高于水位，不受失效影响。

### 并发

发布、失效、读取可并发进行。索引由互斥锁保护；后端写入先于索引登记（写失败不留索引垃圾），
索引移除先于后端删除（删除失败立即可读性归零）。竞态下读取要么看到旧完整版本、
要么看到新完整版本，要么触发一次再生，结果始终自洽。

### 失败与重试

- 回源渲染与后端读写均按**有界指数退避**重试（`RetryConfig{MaxAttempts, BaseDelay, MaxDelay}`）。
- 回写反复失败：索引不登记，不产生半成品条目。
- 后端删除反复失败：索引先移除（内容立即不可读），key 进入待清理队列，
  `SweepOrphans` 在故障恢复后清除，**不会留下无法读取也无法清除的孤儿条目**。

## 配置

| 配置 | 位置 | 说明 |
| --- | --- | --- |
| `mode` | 路由 | `ssg` / `ssr` / `isr` |
| `freshTTLMs` | 路由 | 新鲜期；`<=0` 视为长期有效（SSG 默认行为） |
| `staleTTLMs` | 路由 | 陈旧窗口，仅在 `stalePolicy=serve-stale` 时用于失败兜底 |
| `stalePolicy` | 路由 | `serve-stale`（默认）或 `fail` |
| `tags` | 路由 | 定向失效的标签集合 |
| `RetryConfig` | 代码 | 回源与后端调用的重试次数与退避上下界 |

## 测试

```bash
go test ./...          # 单元与端到端测试
go test ./... -race    # 含并发发布/失效/读取的竞态检测
```

覆盖：三种渲染模式与模式隔离、原子发布、定向失效、并发发布/失效/读取、
有界退避重试、后端故障与孤儿清理、失效事件的乱序/重复/迟到到达。
