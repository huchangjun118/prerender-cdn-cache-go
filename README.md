# prerender-cdn-cache-go

面向动态页面的预渲染与边缘缓存管理服务。支持 SSG / SSR / 增量再生（ISR）三种渲染模式共存，按内容版本原子发布，按标签定向失效，并对并发发布/失效/读取、下游瞬时失败、失效事件乱序/重复/迟到提供完备的一致性保证。

## 设计总览

```
┌─────────────────────────────────────────────────────┐
│                    HTTP Handler                      │
│  /render/{path}  /publish  /invalidate  /admin/*    │
└──────────────┬──────────────────────┬───────────────┘
               │                      │
       ┌───────▼────────┐    ┌────────▼─────────┐
       │   Renderer     │    │   Event Bus        │
       │  (回源渲染)     │    │  (失效事件投递)    │
       └───────┬────────┘    └────────┬──────────┘
               │                      │
       ┌───────▼────────┐    ┌────────▼─────────┐
       │   DataSource   │    │   Cache 索引       │
       │  (下游数据源)   │    │  (条目状态机)      │
       └────────────────┘    └────────┬──────────┘
                                      │
                              ┌───────▼────────┐
                              │   Store         │
                              │  (版本化内容)    │
                              └────────────────┘
```

- **Store**：按路由保存当前已提交的内容版本。内容不可变，发布即整体切换版本指针。
- **Cache**：边缘缓存索引，条目带模式、版本向量、新鲜度状态机与标签高水位。
- **Event Bus**：失效事件投递，按 `(标签, 版本)` 处理，天然幂等。
- **Renderer**：回源渲染，产出内容携带路由声明的模式。
- **Retry**：有界指数退避重试，仅包裹外部调用，不损坏缓存索引。

## 缓存一致性语义

### 核心不变量

1. **模式一致**：每条路由声明唯一渲染模式；缓存条目与读取路径都携带并校验模式，SSG/SSR/ISR 三条读取路径互不串用。
2. **版本原子**：内容不可变；发布是整体版本指针的切换，读取方要么看到完整旧版本，要么看到完整新版本，不存在字段级混合（torn read）。
3. **定向失效**：一次内容变更只让依赖该标签且版本更旧的条目退出缓存，其余标签条目继续命中，不清空整站。
4. **事件幂等**：失效按 `(标签, 版本)` 判定，重复事件不重复失效，迟到事件不复活已清除内容。
5. **最终一致**：乱序/重复/迟到事件处理后的缓存状态，与"清空后全量重建"的结果一致。

### 版本向量

每个内容版本携带 `Deps: map[标签]版本号`，记录其依赖的每个标签在发布时的版本。失效事件携带 `(标签, 新版本号)`。

缓存条目失效条件：`条目.Deps[标签] < 事件版本号`。

| 场景 | 事件 | 条目 Deps | 结果 |
|------|------|-----------|------|
| 正常失效 | `(t1, 2)` | `{t1:1}` | 失效（1 < 2） |
| 重复事件 | `(t1, 2)` | `{t1:1}` | 不失效（已处理） |
| 迟到事件 | `(t1, 1)` | `{t1:2}` | 不失效（1 ≥ 2） |
| 新版本内容 | `(t1, 2)` | `{t1:2}` | 不失效（2 = 2） |
| 其它标签 | `(t2, 1)` | `{t1:1}` | 不失效（无 t2 依赖） |

### 标签高水位

缓存为每个标签维护已处理失效事件的最高版本（高水位）。新写入条目若某标签依赖版本低于高水位，说明其内容在一次失效之后才到达（渲染晚于变更），直接标记为失效。这保证"已失效的旧内容不会借新条目重新进入缓存"。

## 三种渲染模式

| 模式 | 读取路径 | 缓存 | 触发渲染 |
|------|----------|------|----------|
| SSG | 只读 Store 当前版本 | 缓存条目仅用于观测 | 永不（发布时预渲染） |
| SSR | 每次实时渲染 | 不读写缓存 | 每次请求 |
| ISR | 缓存状态机 | 读写缓存 | 未命中/失效/过期时同步或后台再生 |

### SSG（静态预渲染）

发布时渲染并提交到 Store。读取只读 Store，**永不触发回源渲染**——即使下游数据源故障，已发布页面仍正常返回。未发布时读取返回 503。

### SSR（服务端实时渲染）

每次请求都回源渲染，不读写缓存。读取失败返回 502，响应头 `X-Cache: MISS`。

### ISR（增量再生）

缓存条目有三个时间边界：

```
createdAt          freshUntil              staleUntil
  │                  │                       │
  │   fresh 期       │   stale 窗口          │   过期
  │   (直接命中)      │   (返回陈旧+后台再生)  │   (同步再生)
```

- **fresh**：直接命中，`X-Cache: HIT`。
- **stale**：返回陈旧内容（`X-Cache: STALE` + `Warning: 110`），同时触发**后台静默再生**（single-flight 合并同路由并发）。
- **expired**：超出陈旧窗口，同步再生；失败按错误策略处理。
- **invalidated**：已被失效事件清除，不得返回，走同步再生。

## 按内容版本原子发布

发布流程（`POST /publish`）：

1. 更新下游数据源。
2. 锁外渲染新内容（I/O 不阻塞读取）。
3. 锁内原子提交：全局发布序号 `Version` 递增，标签版本向量 `Deps` 一次性推进，整体切换当前版本指针。
4. 按标签投递失效事件 `(标签, 新版本号)`。
5. SSG 模式额外写入缓存条目。

读取方在步骤 3 之前看到旧版本，之后看到新版本，不会看到半成品或字段混合。并发发布/读取测试（`-race`）验证了这一点。

## 按标签定向失效

发布内容时按路由声明的标签集合投递事件。失效判定在缓存侧按版本向量完成：

- 依赖该标签且版本更旧的条目 → 失效。
- 其它标签的条目 → 继续命中。
- 不触发整站清空。

示例：路由 `/a` 带标签 `t1`，`/b` 带标签 `t2`，`/c` 带 `t1+t2`。发布 `/a`（t1 版本 1→2）后：`/a`、`/c` 失效，`/b` 保持命中。

## 并发发布、失效与读取

- 缓存索引的所有变更（Get/Put/Invalidate/Delete/Clear）在同一把锁内完成。
- `Get` 在锁内算定状态并返回，读取方在锁外使用不可变内容是安全的。
- `Put` 整体替换条目，不做字段合并。
- 发布的标签版本推进与内容提交在 Store 的同一临界区内完成。
- 再生（regenerate）在锁外渲染，通过以下机制保证一致性：
  - **渲染前后标签版本比对**：若渲染期间有新发布，丢弃结果并重试（独立宽松预算，非退避等待）。
  - **标签高水位**：若写入时事件已先于渲染到达，条目标记为失效。
  - **single-flight**：同路由的并发再生合并为一次。

## 陈旧窗口与再生失败策略

ISR 再生失败时，在"返回陈旧内容"与"返回错误"之间做明确选择，行为可从响应状态/头观察：

| 策略 | 场景 | 行为 | 响应头 |
|------|------|------|--------|
| `stale-if-error` | stale 窗口内再生失败 | 返回陈旧内容 | `X-Cache: STALE`, `Warning: 110` |
| `stale-if-error` | 超出 stale 窗口 | 返回错误 | `504`, `X-Cache: EXPIRED`, `Warning: 111` |
| `error` | 任意再生失败 | 返回错误 | `504`, `X-Cache: EXPIRED`, `Warning: 111` |

SSR 渲染失败直接返回 502（`X-Cache: MISS`, `Warning: 111`）。

## 下游失败与有界重试

回源（数据源）瞬时失败时，按**有界指数退避 + 抖动**重试：

- 默认最多 3 次尝试，初始退避 20ms，上限 500ms，乘数 2，抖动 0.2。
- 仅重试可重试错误（`ErrDownstream`）；`ErrNotFound` 等不可重试错误立即返回。
- 上下文取消立即停止。

**索引保护**：重试只包裹外部调用（渲染），缓存索引仅在渲染成功后才提交。因此：

- 反复失败不会损坏缓存索引。
- 不会留下无法读取也无法清除的孤儿条目（失败路径不写入半成品条目）。
- 管理接口 `/admin/cache` 可随时观测索引状态。

## 失效事件：乱序、重复、迟到

事件携带 `(标签, 版本)`，处理是幂等的：

- **乱序**：`(t1,3)` 先到、`(t1,1)` 后到——高版本先失效，低版本不复活。
- **重复**：相同 `EventID` 的事件只处理一次（计数可观测）。
- **迟到**：事件版本不高于条目依赖版本时不失效；高水位保证旧内容不复活。

事件总线支持同步（默认）与异步（`AsyncEvents`）两种模式。异步模式下事件进入有界队列，由单个 worker 串行处理；`Flush()` 等待所有已投递事件处理完毕。

## 配置

服务通过 `service.Config` 配置：

| 字段 | 默认值 | 说明 |
|------|--------|------|
| `DefaultFreshTTL` | `1m` | ISR 默认新鲜时长 |
| `DefaultStaleWindow` | `5m` | ISR 默认陈旧窗口 |
| `Retry.MaxAttempts` | `3` | 回源失败最大尝试次数 |
| `Retry.InitialBackoff` | `20ms` | 首次退避时长 |
| `Retry.MaxBackoff` | `500ms` | 退避上限 |
| `Retry.Multiplier` | `2` | 退避乘数 |
| `Retry.Jitter` | `0.2` | 抖动系数 |
| `Clock` | `time.Now` | 注入时钟（测试用） |
| `AsyncEvents` | `false` | 异步投递失效事件 |

路由级配置（注册时指定）：

| 字段 | 说明 |
|------|------|
| `Path` | 路由路径 |
| `Mode` | `ssg` / `ssr` / `isr` |
| `Tags` | 内容标签列表 |
| `FreshTTL` | 该路由的新鲜时长（零值取默认） |
| `StaleWindow` | 该路由的陈旧窗口（零值取默认） |
| `ErrorPolicy` | `stale-if-error`（默认）/ `error` |

## HTTP API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/healthz` | 健康检查 |
| GET | `/render/{path}` | 渲染页面（按路由模式读取） |
| POST | `/publish?route={path}` | 发布内容（body 为新内容） |
| POST | `/invalidate` | 提交失效事件（JSON：`tag`、`version`、`event_id`，version 可省略） |
| POST | `/admin/routes` | 注册/更新路由（JSON） |
| GET | `/admin/cache` | 缓存索引快照 |
| GET | `/admin/store` | 已提交版本快照 |
| POST | `/admin/failures?route={path}&n={次数}` | 注入瞬时失败 |
| POST | `/admin/failures?route={path}&forever=1` | 注入持续失败 |
| POST | `/admin/failures?route={path}` | 清除失败注入 |
| POST | `/admin/clear` | 清空缓存索引 |
| POST | `/admin/warmup` | 全量预热（清空后重建所有 ISR 条目） |

### 示例

```bash
# 注册 ISR 路由
curl -X POST http://localhost:8080/admin/routes \
  -d '{"path":"/home","mode":"isr","tags":["t1"],"fresh_ttl_ms":100,"stale_window_ms":1000}'

# 发布内容
curl -X POST "http://localhost:8080/publish?route=/home" -d "hello-v1"

# 读取（首次 MISS，之后 HIT）
curl -i http://localhost:8080/render/home

# 手动失效（省略 version 时使用当前标签版本）
curl -X POST http://localhost:8080/invalidate -d '{"tag":"t1"}'
```

## 响应头

| 响应头 | 值 | 说明 |
|--------|----|------|
| `X-Cache` | `HIT` | 缓存命中（fresh） |
| `X-Cache` | `MISS` | 未命中/同步再生 |
| `X-Cache` | `STALE` | 返回陈旧内容（stale 窗口内） |
| `X-Cache` | `EXPIRED` | 再生失败且无陈旧可返回 |
| `X-Render-Mode` | `ssg`/`ssr`/`isr` | 路由声明的渲染模式 |
| `X-Content-Mode` | `ssg`/`ssr`/`isr` | 内容的实际产出模式 |
| `X-Content-Version` | 整数 | 内容全局发布序号 |
| `Warning` | `110 - "Response is stale"` | 陈旧窗口内返回了陈旧内容 |
| `Warning` | `111 - "Revalidation failed"` | 再生失败 |

## 测试

```bash
# 全部测试
go test ./...

# 并发安全（强烈建议）
go test -race ./...

# 单个包
go test ./internal/cache/ -v
go test ./internal/service/ -v
```

测试覆盖：

- **渲染模式**：SSG 不回源、SSR 实时渲染、ISR fresh/stale/expired 状态机。
- **原子发布**：并发发布与读取，`-race` 验证无撕裂。
- **定向失效**：受影响页面退出缓存，其余页面保持命中。
- **并发发布/失效/读取**：`-race` 验证，最终状态与全量重建一致。
- **陈旧窗口与失败策略**：`stale-if-error` 窗口内返回陈旧、窗口外返回 504；`error` 策略直接报错。
- **失败重试**：瞬时失败重试成功、持续失败返回错误、索引无孤儿条目。
- **乱序/重复/迟到事件**：最高版本生效、重复去重、迟到不复活。
- **模式隔离**：路由模式变更后旧模式条目不得被复用。
- **异步事件**：乱序入队 + Flush 后状态一致。
- **Single-flight**：陈旧窗口内并发读取只触发一次后台再生。
